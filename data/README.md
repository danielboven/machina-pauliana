# data

The database, hand-annotated gold standards, model outputs and figures used in
the research paper. The directory contains both intermediate data from the
case-law pipeline and the datasets used to evaluate its segmentation,
pre-retrieval annotation and final neuro-symbolic reasoning.

## Directory layout

| path | contents |
|---|---|
| [`gold_standard/validation_dataset_pipeline/`](gold_standard/validation_dataset_pipeline/) | 100 manually annotated judgments for evaluating segmentation and the three RAG pre-retrieval labels. |
| [`gold_standard/neuro_symbolic_model/full_judgments/`](gold_standard/neuro_symbolic_model/full_judgments/) | Ten full judgments with a manually annotated Catala input and verdict in an opening YAML metadata block. |
| [`neuro_symbolic_model/inputs/`](neuro_symbolic_model/inputs/) | The ten evaluation cases supplied to the neuro-symbolic model: only the facts and dispute relevant to the contested transaction, not the court's reasoning or decision. |
| [`neuro_symbolic_model/results/`](neuro_symbolic_model/results/) | Model output for every combination of three LLMs and `k = 0, 5, 10` retrieved judgments. |
| [`neuro_symbolic_model/kwalitatieve_data_neuro_symbolic_model.pdf`](neuro_symbolic_model/kwalitatieve_data_neuro_symbolic_model.pdf) and [`.tex`](neuro_symbolic_model/kwalitatieve_data_neuro_symbolic_model.tex) | Qualitative data containing the gold judgments and model output, as a PDF with its LaTeX source, allowing the legal method to be applied to the model's reasoning. |
| [`rag/`](rag/) | Pre-retrieval annotations produced by GPT and Mistral for the 100-judgment validation set, as JSONL. |
| [`figures/`](figures/) | PDF figures (most with an SVG copy) generated by the scripts in [`evaluation`](../evaluation/) and could be used in the research paper. |

## Gold standards

The pipeline validation files are Markdown judgments with an opening YAML
metadata block:

```yaml
---
ecli: ECLI:NL:GHAMS:2017:3795
onverplicht: false
wetenschap: false
benadeling_schuldeisers: false
---
```

`True` means that the court itself rules on that requirement of art. 42 Fw.
Within the Markdown body, `<!-- @feiten -->`, `<!-- @overwegingen -->` and the
other section markers open a segment. It ends at the next marker or at the end
of the file.

The neuro-symbolic gold files use the same opening YAML metadata block, but
record the complete input/output schema of the Catala model. The body contains
the full judgment for reproducibility. The ten-case set combines seven
JOR-published decisions with three 2026 first-instance judgments delivered
after the RAG database snapshot was built. Their corresponding files in
[`neuro_symbolic_model/inputs/`](neuro_symbolic_model/inputs/) are deliberately
shorter: they are the natural-language inputs used for the final evaluation.

## Generated outputs

Each file under `neuro_symbolic_model/results/` represents one `(model, k)` run:

```json
{
  "model": "gpt-5.5",
  "k": 5,
  "results": {
    "ECLI_NL_RBAMS_2026_3787": {}
  }
}
```

Runs with `k >= 1` also carry a top-level `ablation` object (between `k` and
`results`) listing, per case, the judgments from the same proceedings that were
removed from retrieval; see [`evaluation/README.md`](../evaluation/README.md).
The result object contains the routines' textual reasoning, the resolved Catala
inputs and the final `vernietigbaar` verdict. Names beginning with `JOR_` refer
to cases sourced by their *Jurisprudentie Onderneming & Recht* identifier
(whenever they do not have a known ECLI tag).

Files under `rag/` contain one JSON object per line and judgment. Each of the
three labels has a boolean `waarde` and a supporting verbatim `citaat`.
An empty citation should go with a negative label.

## Database snapshot

[`machina_pauliana.sql`](machina_pauliana.sql) is a dump of the Postgres/pgvector
database used for RAG. It contains the judgments, segmented sections,
procedural-chain relations, embeddings and pre-retrieval labels produced with
`mistral-medium-3.5-128b:fp8`. See [`rag/README.md`](../rag/README.md) for the
schema and the commands that build the store.

See [`evaluation/README.md`](../evaluation/README.md) for how the datasets and
figures are generated and scored.
